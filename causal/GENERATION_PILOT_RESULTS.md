# Member C prompt pilot, 22 November 2026

Model: `deepseek-v4.1-flash-1017`. Dataset:
`causal/datasets/node03/n3_all_observations.json`. The five questions were
sampled with seed `33550336`. Each arm generated one candidate per question,
with one API attempt per candidate. Both runs used the same sampled questions.
The target count was chosen before each run and the official answer set was
consulted only in the offline analysis.

Offline inspection showed that only two sampled questions admit a valid
one-edge graph. All three infeasible one-edge calls ended with the provider's
`length` finish reason at the configured 2,048 output-token limit. Four
questions admit a valid two-edge graph. The targeted arm succeeded on all four;
the one infeasible call again ended at the output limit.

For the two-edge target, question `n2_022` produced a valid two-edge graph
different from the valid one-edge graph generated by the no-target arm.
The other feasible questions produced the same graph in both arms. Across the
four feasible questions, the targeted arm used 4,412 tokens and the no-target
arm used 3,133 tokens.

These ten paired observations diagnose prompt behavior. They do not establish
an improvement in Recovery or compare adaptive allocation strategies. A
controller should learn from validity and novelty feedback without seeing
the offline answer-set feasibility labels. Infeasible targets are especially
costly with this model and output limit.
